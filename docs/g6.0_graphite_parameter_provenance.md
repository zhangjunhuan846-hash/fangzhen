# Gate 6.0 — Graphite 参数 provenance 审计

> **这一步不做任何优化。** 目的是建立一张**可追溯的** graphite 参数来源表，
> 让每一行都能回答：这个数从哪来？是直接测量 / 文献 / 拟合 / 假定？
> 模型真的消费它吗？不确定度多大？
>
> 产出：
> - `outputs/graphite/g6_0_parameter_set.json`（参数集**原样 dump**，89 个 key，含 callable 的函数名与源文件）
> - 本文（逐项审计）
> - `scripts/graphite/dump_graphite_parameters.py`、`list_graphite_parameter_keys.py`
>
> **状态：IN PROGRESS。** "current value" 列已填齐；"source" 列需要逐项回溯，
> 标 ⚠️ 的是**审计中发现的、需要决策的**问题。

## 0. 两个必须先说的结构性发现

### ① graphite 参数挂在 **`Positive electrode ...`** 名下，不在 `Negative electrode ...`

`configs/datasets.yaml` 的 `sintef_graphite` 块已经写明：

```yaml
cell_configuration: "half_cell"
working_electrode: "positive"              # PyBaMM slot holding graphite
physical_working_electrode: "graphite_negative"
counter_electrode: "lithium_metal"
```

半电池参数集把**工作电极映射到 PyBaMM 的 positive 槽**。
所以 `Positive electrode OCP` 才是石墨 OCP，
而 `Negative electrode OCP [V] = 0.0` 是**锂金属对电极**（钉在 0）。

> **审计含义**：任何"按名字取参数"的脚本在这里都会取错。
> dump 脚本第一版就有一半 key 报 ABSENT，正是因为按了全电池的命名去找。
> **这个坑必须写进文档，否则以后每个新人都会踩。**

### ② ⚠️ **`Positive particle diffusivity` 是函数，不是标量**

```text
Positive particle diffusivity [m2.s-1]   CALLABLE graphite_diffusivity_Ecker2015
Positive electrode OCP [V]               CALLABLE graphite_ocp_Ecker2015
Positive electrode exchange-current      CALLABLE graphite_electrolyte_exchange_current_density_Ecker2015
  density [A.m-2]
Electrolyte diffusivity [m2.s-1]         CALLABLE electrolyte_diffusivity_Ecker2015
Electrolyte conductivity [S.m-1]         CALLABLE electrolyte_conductivity_Ecker2015
```

> **这对 G5 → G6 的迁移是决定性的**：
> **G5 全链条辨识的是一个标量 $D_s$。graphite 的 $D_s$ 是 $D_s(x)$ —— 化学计量数的函数。**
>
> 所以 G6 的辨识问题**不是**"把 G5 换个数据集再跑一遍"，而是
> **"如何辨识一个函数值参数"**。这直接落在平台能力矩阵的
> `representable` 一栏上：平台当前**无法表示函数型参数**（G5 阶段已记录，
> $k_0$ 就是因此不能进第一版向量）。
>
> **G6 的第一个技术问题因此是：$D_s(x)$ 用什么样的有限维表示来做辨识**
> （分段常数？基函数展开？还是先在若干 $x$ 点上逐点定？）——
> **这个问题必须在 G6.2 之前解决。**

## 2. 与 SINTEF 实测数据的对应关系

平台已经有（来自 `configs/datasets.yaml`）：

```text
pOCV            → 派生 OCP（external/pybamm-input-data/graphite_ocp_Ecker2015.csv）
GITT            → 派生 apparent D_s
目录 metadata   → geometry / loading（data/metadata.csv）
容量一致化       → Q_model == Q_ref
rate data       → 倍率行为
```

**已经存在的跨电芯保留意见**（配置里已写明，这里重申）：

> GITT 电芯 **063b77** 与 p-OCV 电芯 **4ccc47** **不是同一颗**。
> 因此把 D_s 套到 p-OCV 回放上属于**跨电芯检验**，
> B1/B1.6 报告里一律写作 **consistency check，不是 validation**。

**G6.0 的下一步**就是把这五类实测与上表逐行对应起来，
凡是对不上的（#1 #5 #8 #15 #20）都要给出结论：**是实测、是文献、还是假定。**

## 3. 从 G5 迁移过来、必须记住的四条

| # | 从 G5 学到的 | 对 G6 的直接含义 |
|---|---|---|
| 1 | **拟合好 ≠ 参数对**（G5.2） | graphite 上同样要报 rate-dependent 残差，不能只看 RMSE |
| 2 | **曲线主要约束 $\tau_d=R_p^2/D_s$**（G5.3） | 单条 graphite 曲线同样**不足以**分开 $R_p$ 与 $D_s(x)$ |
| 3 | **$R_p$ 误差以平方放大到 $D_s$**（G5.5a，$\beta=2.075$） | 粒径不确定度**必须先定**，否则 $D_s$ 的分辨率无从谈起 |
| 4 | **残差最小 ≠ 精度最高**（G5.4） | 定 G6 判据时不能用"残差更小"选方案 |

**另外**：graphite 的 $D_s$ 是**函数**（发现 ②），所以第 2 条的退化
在 graphite 上会比 Chen2020 **更严重** —— 待辨识的自由度更多，而约束还是那几条曲线。

## 5. 边界

- 本表**只覆盖 graphite 工作电极**；对电极（Li 金属）、电解液、SEI 模块暂不审计。
- **没有任何一项被判定为"可辨识"** —— 本步只做来源，不做辨识性。
- ⚠️ 行的存在**不是错误**，是审计的正常产出：一个参数集如果所有行都能填满，
  通常意味着已经有人做过这项工作，而 PyBaMM 内置集**没有**。
