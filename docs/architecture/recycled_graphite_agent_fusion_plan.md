## 0. 先说三条会改变结论的事实

在讨论"融合"之前必须先看清这三条，否则会把一个**不该现在做**的事排进关键路径。

### ① 你的实验设计和上游的 Agent 在同一个轴上**恰好相反**

| | 上游 Battery-Sim-Agent | 你现在的回收石墨实验 |
|---|---|---|
| 数据 | **sim-vs-sim**（自己造靶，100 例 × 3 族） | **真实实验**，每组 ≥3 颗平行电芯 |
| 待辨识的东西 | 电池**设计参数**（厚度 / 载量 / 正极扩散系数…） | 材料**结构状态**（热处理温度造成的 D_s、OCP 变化） |
| Agent 的作用 | **提参数**（它就是主角） | **没有位置** —— 你的自变量是温度档，不是待猜的数 |

**这条最关键**：你的实验里，**"提什么参数"这件事已经被实验设计定死了**（四个温度档 + 一个未处理参照系）。
Agent 的核心功能（在参数空间里搜索候选）**在这个实验里没有落脚点**。

→ 所以"融合"不能是"把 Agent 接到回收石墨实验上"。那是把搜索器接到一个不需要搜索的地方。

### ② 上游的桥**从程序上无法**驱动你的实验

实测（`battery_agent/param_capability.py`，本地加固副本）：

```text
PARAMETERS 一共 14 个逻辑名，全部映射到 "Positive electrode ..." / "Negative electrode ..." 的
**全电池**双电极键，且都带 models: ("SPM","SPMe","DFN")
  electrode_thickness / electrode_area / electrode_height / electrode_width /
  active_material_volume_fraction / porosity / particle_radius / temperature /
  max_concentration / initial_concentration / nominal_capacity /
  particle_diffusivity / exchange_current_density / ocp
```

对你的石墨 **half-cell**（石墨在**正极槽位**）来说：

- 桥没有任何"半电池"概念。`SUPPORTED_MODELS = ("SPM","SPMe","DFN")` 全是全电池模型。
- 你的半电池回放**必须**走 `run_baseline_cell` + `half_cell` 选项 + `initialisation` 块，
  否则 t=0 初值就违反 `Maximum voltage [V]`（这一条平台内踩过）。
- 桥的 `check_reserved_key` 把 `initial_state` 列为**保留键**，且只认两种方法
  （`fixed_initial_concentration` / `initial_soc`）—— 而你的实验恰恰要动的就是**初值/OCP 接线**。

→ **不是"配置一下就能用"，是桥的抽象层与半电池不匹配。**

### ③ 唯一真正缺的融合件，是**曲线型参数（OCP）**，而它已被平台内部解决

`agent_platform_fusion.md` §3③ 说得对：`ocp` 与 `particle_diffusivity` 在桥里直接 `BridgeError`，
"而这一批实验恰恰要改 OCP"。

**但方案 ② + 你的 p-OCV 双支实测表，走的是另一条路，已经通了**：

```text
实测 p-OCV 双支表
  → RecycledGraphiteAdapter.ocp_table_path()        (battery_sim/datasets/recycled_graphite.py:383)
  → 平台内部把 OCP 替进参数集
  → run_baseline_cell 回放
```

**这条路根本不需要桥。** 桥的 `ocp` 白名单条目是为"Agent 提议一条 OCP 曲线"设计的，
而你的场景是"实验测出一条 OCP 曲线，平台读它" —— 已经有现成通路。

⇒ 结论：**③ 不是"必须进 v0.1.1 的融合项"，它在你的实验里根本不走融合这条路。**

## 2. A：能直接抄的两件守卫（**这几天就能做，与 Agent 无关**）

这两件在 `agent_platform_gap.md` §1 已被认定为"本平台确实缺"，并且**恰好是接真实回收石墨数据的高风险位**。

### A1. 单位层（affine）—— 优先级最高

| | |
|---|---|
| 上游踩过的坑 | `degC → K` 当**乘法**算，35 °C 变成 **9560.25 K** —— 一个"看起来成功"的错答案 |
| 上游的修法 | 单位声明为 `(scale, offset)` 对；**整条链只有一条换算路径**；用普通比例表声明 `degC` 会被测试拦下 |
| 你的现状 | `grep UNIT_TO_SI / UNIT_AFFINE / affine` → **零命中** |
| 为什么对你尤为危险 | 你的数据来自**真实仪器导出**（Basytec / 工作站），单位写法五花八门；带 offset 的单位（°C、mV-vs-V）一旦当乘法处理就是**静默错值** |

**建议的落地形式**（照抄结构，不用照抄名字）：

```text
新增 battery_sim/datasets/units.py（或进 template.py）：
  - 一张 (单位字符串) -> (scale, offset) 表
  - to_si(value, unit) 唯一入口，offset==0 就是普通比例
  - adapter 里**禁止**出现裸乘法换算（测试断言拦）
  - 加一条测试：用比例表声明 °C 必须失败
```

⚠️ 这条**不需要动 `v0.1.0-platform`**：新增文件 + adapter 内改调用，属 additive。

### A2. 「模型根本不读这个键」的守卫

你现在的能力分级（STATUS.md）已经有五级：
`representable → accepted → resolved → numerically_active → identifiable`。

**这和上游的守卫是同一个洞察**（上游：`porosity` 在 SPM 下写了、记了、RMSE 逐位不变）。
所以这条**你其实已经比上游做得细**，缺的只是**一个便宜的自动判据**：

```text
判据（零成本）：覆盖该键 → 跑一遍 → 轨迹与未覆盖**逐位相同** ⇒ numerically_inactive
```

**为什么现在值得做成自动的**：你的实验要动的是**同族参数在不同样品间比较**
（CG-AR / 600 / 800 / 900 或 RG_raw / RG_500 / RG_800），
一旦某个键在其中某个样品上"其实没被消费"，**四个样品的比较里就会有一列其实是常量** ——
而它会伪装成"这个样品对这个参数不敏感"。**跨样品比较时这个假象特别贵。**

## 3. B：真正的融合 —— **L3 带宽图生成 Agent 的候选白名单**

这是唯一一件"两边各出一半、单独谁都做不出来"的事。

### 3.1 它解决的问题

Agent 侧有一个**至今没解决的真 bug**（`BORROW_NOTES.md` §5）：

```text
prompt.yaml 的知识文本用 snake_case：SEI_solvent_diffusivity_m2_s-1 …
degradation_pipeline.py 的白名单用 PyBaMM 风格：'SEI solvent diffusivity [m2.s-1]' …
⇒ 两套名字**零重叠** ⇒ 模型照知识文本写 → 名字不在白名单 → 被过滤 → 空列表
  ⇒ 撞进那个 while 循环（原版最长 10000 秒空转）
```

**上游的修法是"把名字对齐"**（`prompt.yaml` 里补一句"请用列表里的精确拼写"）。
**你的修法应该不一样**：白名单**不该由人手写**，应该**由 L3 的带宽图生成**。

### 3.2 为什么这个修法在你这边成立

平台已经有了它需要的一切：

| 需要的 | 现状 |
|---|---|
| 逐窗口 1 mV 带宽 + 五词判定 | ✅ `identification/parameter_report.py --mode material` |
| 石墨半电池的 GITT QC | ✅ `protocol_type=GITT` + `pulse_duration_s` 声明，两次一致性检查进 `user_tools/validate.py` |
| 激励地图的估计器（双向都跑过） | ✅ G6.1b-1 / G6.1c |

⇒ 融合的**第一个动作不是写桥**，是这一句：

```text
让 Agent 的候选参数集 = L3 说 identifiable / bounded 的那些键
```

**这同时解决了三件事**：
1. Agent 侧那个"两套名字零重叠"的 bug（白名单从图里长出来，不是手写）；
2. Agent 不会去提议数据里**根本没有激励**能定住的参数（G6.1c 已证：放电扫程 239 个窗口**一个都不合格**）；
3. 论文里 Agent 的每一次提议**都有出处**（第几个窗口、什么判定词）。

### 3.3 ⚠️ 但这里有一个必须提前说清的**上限**

`agent_platform_fusion.md` §2 已经写死了：

> 融合**不会**让参数变得可辨识。G6.1b/1c 已证**瓶颈在激励，不在参数化** ——
> Agent 再聪明也造不出数据里没有的激励。所以融合的价值上限是**如实说出哪里不可辨识**，
> 不是"辨识出来"。

**这对你的回收石墨实验是硬约束**：G6.1c 在公开石墨数据上实测
**225 个放电窗口里 0 个、230 个充电窗口里 3 个**能达到 0.30 dex。
⇒ 你的 L3 大概率也报不出点估计，产出形态是**地图的形状**，不是一条 `D_s(x)`。

**所以融合在你这批数据上的产出，最可能是"一份逐窗口判定表"**，
而不是"四个样品各一条漂亮的扩散系数曲线"。**这个预期必须现在就有**，
否则实验做完会以为融合失败了。

### 3.4 还有一个**变量不匹配**

Agent 的逻辑名是**电池设计参数**（`positive electrode thickness` 等），
而你要比较的是**材料状态差异**（热处理温度 → D_s / OCP 的变化）。

中间缺一层：**"温度档"不是参数、"D_s"是参数、"这个窗口的 D_s 能不能定住"是判定**。

⇒ 融合的输出**不该是"Agent 找到了 D_s"**，而该是：

```text
对每个样品、每个窗口：判定词 → 汇总成一张表 → 四个样品比**表的形状**
```

Agent 在这里的角色退化成：**在 L3 说"可辨识"的那几个窗口上跑一次局部优化，作为地图的数值填充**，
而不是"自主提参数"。**如果做不到这个退化，就不该接 Agent。**

## 4. C：论文对照 —— 这是融合里唯一"现在就确定有价值"的部分

`agent_platform_fusion.md` §1 的定位很准：

> **它回答"参数能不能被反演准"，本平台回答"这个参数在这份数据里到底能不能被定住、以及它凭什么值得信"。**

对你的回收石墨实验，这个对照可以写成**一句有数据支撑的话**：

| | 上游方法在你的数据上会怎么做 | 你的平台的做法 |
|---|---|---|
| 目标 | 让 sim 曲线贴合实测曲线（loss 降下去） | 判定每个窗口能不能定住 |
| 已知失效模式 | **G5.2 实证：真值不是最优解** —— 错误模型假设下，偏 **−25 %** 的参数拟合反而好 **3.4×** | 判据不设"RMSE 小于 X mV" |
| 面对"四个样品" | 报 4 组拟合好的参数 | 报 4 张带宽图 + 判定等级 → 比**形状**与**方向差异**（同状态充/放电窗口差 3.5–5×） |

**⚠️ 一个必须写进去的自我限定**：G5.2 那个"偏 −25 % 反而好 3.4×"是**合成实验**里的结论。
不能直接写成"上游方法在你的真实数据上会失败" —— 只能写成
**"本平台的判据设计是为了避免这一类失效；上游方法的目标函数没有对应机制。"**
（这是措辞红线：surrogate ≠ validation。）

## 5. 顺序（本文最重要的一节）

```text
现在  ──── ① 定死跑哪一套 + 三条红线（附件 B §1/A1）  ← 与 Agent 无关，纯实验侧
              ↓
          ② L1/L2：CG-AR（或 RG_raw）先过
              ↓
          ③ 补 A1 单位层（接真实仪器文件之前）
              ↓
          ④ L3 出带宽图 ──────────────► **融合的入口在这里**
              ↓                              ↓
          ⑤ L4 冻结参数预测 1C        ⑥ 带宽图 → Agent 候选白名单（B）
                                           ↓
                                     ⑦ Agent 在"可辨识窗口"上做数值填充
```

**四条硬规矩**：

1. **①②③ 之前不许碰 Agent。** 附件 B §2 已经写死："A2 / A3 / A4 / A6 任一条没定，不许开跑。"
   融合更要排在后面 —— 否则是在一个还没有数据的东西上做集成。
2. **L4 的 holdout 绝不参与任何一轮 Agent 迭代**（含"以调参为目的的试跑"）。
   这是 `agent_platform_fusion.md` §7 的融合成功判据第 3 条。
3. **Agent 不得回改 L4 冻结的参数**（回改即 L4 作废，预注册已冻结）。
4. **融合后不许把目标写成"RMSE 更低"** —— 平台侧判据从一开始就不是 RMSE
   （预注册 §3.4 明写"不设 RMSE 必须小于 X mV 的门"）。

## 7. 明确不做（照抄 `agent_platform_fusion.md` §4，并经本次复核确认）

| 不做 | 理由 |
|---|---|
| 把 LLM 放进平台主循环 | 违反 `v0.1.0-platform` = `ee2fb36` 冻结 + 导师明确"不要再扩展 Agent" |
| 把 BO / CMA-ES 搬进平台 | 那是 Agent 的**基线**不是平台的**判据**；而且**算法本身也不是上游自研的**（BO 走 `ax.service.ax_client.AxClient`，CMA-ES 走 `import cma`） |
| **改上游的 `param_capability.py` 去支持半电池** | 改动量大（14 个键全是 Positive 全电池 + 3 个模型），**而收益＝0**（见 §0②：你的实验不需要 Agent 提参数） |
| 把治理层（`dataset_role` / 预注册 / provenance）搬到 Agent 侧 | 搬过去只会变成一份没人校验的声明 —— 正是平台一直在防的"看起来被接受了其实什么都没做" |
| **先做多参数联合辨识** | G6.1b/1c 已证：**瓶颈在激励不在参数化** |
| 让 Agent 回改 L4 参数 | 回改即 L4 作废 |

## 8. 一句话总结

**对你的回收石墨实验来说，"融合"不是把 Agent 接进实验（那里没有它的位置），
而是三件性质不同的事：**

1. **A（守卫）**：单位层 + 消费守卫 —— 代码现成，属 `v0.1.1` **工程补丁**，接真实仪器前做；
2. **B（真融合）**：L3 带宽图 → Agent 候选白名单 —— **排在 L3 之后**，解决的是
   Agent 侧那个悬而未决的 bug，且上限是"如实说出哪里不可辨识"；
3. **C（叙事）**：它问"能不能反演准"，你问"能不能被定住、凭什么值得信" —— **写论文时用**。

⇒ **现在这个时间点上，融合的正确动作是：什么都不做，先把实验跑起来。**
唯一该提前做的，是 §2 的两件守卫（因为它们接真实数据前必须到位，且与 Agent 无关）。
